## Context

The kit's ontology was Markdown-only: easy for humans and agents to read and diff, but nothing
about it was machine-readable, and it was hand-maintained — exactly the two-representations-drift
problem the rest of the kit exists to close for domain vocabulary generally.

## Decision

`ontology.ttl` becomes the authoritative file; `ontology.md` becomes generated output, regenerated
by a new `build-ontology.mjs` (migrate once if no `.ttl` exists, then always render), enforced by a
new CI staleness check. A small kit-owned OWL vocabulary (`kit:` namespace) gives every ontology
section a formal type. Considered and rejected: hand-maintaining both files with a drift check
instead of generation (more flexible, but drift-prone); shipping Narrative's own files as kit
templates (rejected — Narrative is a separate tool this kit doesn't own, so the spec recommends it
but only scaffolds on explicit agreement, using this repository's own files as the worked example).

## Consequences

Editing the ontology moves from `ontology.md` to `ontology.ttl`; the `.md` becomes a reviewable,
generated artifact, similar to `Narrative.md`. A new `docs/ai-agent-install.md` becomes the primary
onboarding path for an AI agent given a short "add the ontology kit" prompt. The `kit:` vocabulary
is now a design commitment — widening it later is a breaking change to the parser/renderer, not a
docs update. Implementation is not yet started; this PR is spec and plan only.
